# Влияние матрицы смежности на качество GNN

Эксперимент: берём MNIST, перемешиваем признаки одной фиксированной
перестановкой, объявляем каждый признак вершиной графа. Фиксируем архитектуру
GNN и все гиперпараметры. **Меняем только матрицу смежности A** и смотрим, как
меняются метрики.

Документы: [PLAN.md](docs/PLAN.md) - постановка и обоснование, [RUNBOOK.md](docs/RUNBOOK.md) -
что делать на GPU-машине, [SETUP.md](docs/SETUP.md) - окружение.

Первая серия (эта страница) завершена: 110 прогонов, `mlp ≫ grid4 ≫ empty >
complete`, выводы в [FINDINGS.md](docs/FINDINGS.md). Идёт вторая серия - ось глубины
и архитектуры (GAT, GIN), гипотезы и критерии зафиксированы в
[PREREGISTRATION.md](docs/PREREGISTRATION.md), запуск - в разделе «Вторая серия»
[RUNBOOK.md](docs/RUNBOOK.md). Журнал всех идей, включая опровергнутые -
[IDEAS.md](docs/IDEAS.md).

## Главное, что нужно понимать про эту задачу

**Граф - единственный источник идентичности вершины.** Признак вершины -
скаляр (значение пикселя), вершины не пронумерованы, свёртка перестановочно
эквивариантна, readout - среднее. Значит модель физически не может отличить
вершину `v` от вершины `u` ничем, кроме структуры их окрестностей в `A`.

Отсюда обе границы шкалы считаются на бумаге, ещё до обучения:

```
A = 0      ->  A+I = I   ->  Â = I     ->  вершины не общаются
                                            модель = функция гистограммы интенсивностей
A = K_d    ->  A+I = J   ->  Â = J/d   ->  после 1-го слоя все вершины одинаковы
                                            модель = функция среднего значения пикселя
```

Это и есть обязательная проверка кода (`src/sanity.py`): если порядок
`mlp ≫ grid4 ≫ empty > complete` нарушен, значит где-то баг, и эксперимент
измерит его, а не влияние графа.

**Перестановка π ничего не меняет математически.** `P_π X` на графе `P_π A P_π^T`
изоморфно исходной задаче. π нужна не для сложности, а как запрет на читерство:
нельзя строить граф из координат пикселей, потому что после перемешивания
координаты неизвестны. Поэтому решётка 28×28, перенесённая через известную нам
π, - это **оракул** (верхняя граница), а не метод. Честные кандидаты строятся
только по обучающей выборке.

**Главный контроль - изоморфный, но несогласованный граф.** Берём решётку и
приклеиваем к вершинам случайной σ вместо π. У неё побитово те же `|E|`,
плотность, спектр, диаметр, кластеризация - отличается только привязка к
данным. Если оракул сильно бьёт этот контроль, то

> m(A) не является функцией класса изоморфизма A,

а значит структурные характеристики графа в принципе не могут предсказать
качество. Предсказывать должны дескрипторы, зависящие от данных - энергия
Дирихле и ассортативность сигнала (GCN это низкочастотный фильтр, и хорош тот
граф, на котором сигнал гладкий).

На полном разрешении это уже видно до всякого обучения:

| | grid4 | grid4_misaligned |
|---|---|---|
| все структурные дескрипторы | совпадают побитово | совпадают побитово |
| энергия Дирихле | 0.4208 | 2.0268 |
| ассортативность сигнала | 0.8111 | 0.0039 |

## Перенос в чужой репозиторий

Копировать папку целиком **нельзя**: `.venv` весит 1.3 ГБ и непереносим — в
`.venv/bin/*` зашиты абсолютные пути машины, где он создан. Плюс 23 МБ данных
MNIST, которые качаются заново одной командой.

Что делать: положить папку под git с приложенным `.gitignore` — он всё лишнее
уже отсекает. В репозиторий уедет **2.6 МБ**: код, документы, конфиг и
результаты экспериментов.

У себя после клонирования:

```bash
./setup_env.sh
```

Соберёт окружение и скачает MNIST. Проверить: `python src/model.py --dev`.

Одна оговорка: четыре файла в `results/` названы кириллицей
(`отчёт_краткий.pdf` и другие). На Linux и macOS всё в порядке, а вот на
Windows с настройками git по умолчанию имена могут поехать. Если в команде
есть Windows, эти файлы стоит переименовать латиницей до первого коммита.

## Кандидаты A

Шесть групп, каждая отвечает на свой вопрос.

**R - референсы, границы шкалы.** `mlp` (обычный MLP на сырых признаках,
потолок ~98%), `empty`, `complete`.

**O - оракулы**, используют знание π: `grid4`, `grid8`. Помечены `honest=False`.

**D - data-driven**, строятся **только по train**: `knn_corr_k4/k8/k16`,
`thr_corr`. Это честные методы - они не знают π и восстанавливают структуру
из корреляций между пикселями.

**C - контроли.** `grid4_misaligned` (главный), `er_grid4`, `er_knn8`,
`regular4`, `config_knn8`. Каждый согласован по плотности со своим оригиналом.
Плюс `grid4_misaligned_s2 … s10` - девять дополнительных перестановок σ для
H1-strong (см. docs/PREREGISTRATION.md): базовый контроль держится на одной σ,
это выборка из десяти.

> Зачем они. Без контроля «kNN лучше пустого графа» не значит ничего: может,
> дело просто в количестве рёбер. Правило: ни одно утверждение «граф X
> помогает» не принимается без сравнения со случайным графом той же плотности.

**W - кривая деградации.** `ws_p005 ... ws_p1`: решётка, у которой доля `p`
рёбер переставлена двойными перестановками. Это не классический
Уоттс-Строгатц: перепроводка одного конца ребра портит степени, а двойная
перестановка сохраняет степенную последовательность **точно**. Значит по
кривой меняется ровно одно - локальность связей.

**P - патологии:** `star`, `path`, `blocks`. Задают шкалу.

## Как запускать

```bash
python src/prepare_data.py          # один раз, нужен интернет
python src/sanity.py --dev          # гейт, ~12 мин на CPU
python src/calibrate.py             # выбор числа эпох (на GPU-машине)
python src/graph_stats.py           # дескрипторы, ДО обучения
python src/run_all.py               # основной прогон

# синтетика и алгоритм построения графа
python src/synth.py                 # генератор + его самопроверки
python src/eval_builders.py         # какой способ построения ближе к истине
python src/refine.py --rule keep    # петля улучшения графа (keep - контроль)
python src/analyze.py               # таблица, графики, гипотезы
```

Флаг `--dev` включает пулинг 2×2 (`d = 196`) и уменьшенную выборку - цикл
правки занимает секунды вместо минут. На финальные прогоны не используется.

Порядок важен в двух местах:

* **гейт до основного прогона** - иначе 110 прогонов измерят баг;
* **дескрипторы до обучения** - иначе гипотезы H2 и H3 превращаются из
  предсказаний в подгонку под уже увиденные результаты.

## Решения, которые стоит уметь объяснить

**Почему без torch_geometric.** Топология одна на всю выборку, различаются
только признаки вершин. Значит слой GNN - это обычный батчевый матмул с
предпосчитанной `Â`, а не сборка `edge_index` на каждый батч. Численно
тождественно `GCNConv`, но кратно быстрее на `d = 784`. Побочный плюс: все
кандидаты - плотные матрицы одного размера, поэтому решётка и полный граф
считаются одинаковое время, и нет конфаунда «плотный граф медленнее».

**Раскладка тензора `[d, B, F]`, а не `[B, d, F]`.** При такой раскладке
распространение - это `Â @ h.reshape(d, B*F)`, один большой GEMM по непрерывной
памяти. При `[B, d, F]` тот же расчёт превращается в B мелких матмулов или
требует копию на каждом слое.

**Порядок `(Â H) W` против `Â (H W)`** выбирается по стоимости: матрицы
коммутируют (`Â` действует по оси вершин, `W` по оси признаков), результат
тождественный, а цена разная - на первом слое `F_in = 1`, и распространить
дешевле до расширения признаков. Проверка коммутации есть в `model.py`, чтобы
эта оптимизация не поменяла модель незаметно.

**Только глобальная нормализация `x/255`.** По-пиксельную стандартизацию
делать нельзя: у краевых пикселей `std ≈ 0`, деление на неё раздувает шум в
огромные значения.

**Никаких positional encodings.** Они дали бы модели идентичность вершины в
обход `A` - а именно её отсутствие делает эксперимент осмысленным. В
`build_model` стоит явная проверка.

**Мёртвые пиксели.** 69 из 784 пикселей MNIST константны на train, корреляция
с ними не определена. Они остаются изолированными вершинами в kNN-графах, и их
число логируется. Ребро проводится только к соседям с положительной
корреляцией - иначе `argsort` разрешает ничьи на нуле произвольно и добирает
соседей чистым шумом.

**Сид управляет только инициализацией весов и порядком батчей.** Разбиение
данных, π и случайные графы от него не зависят - у графов свой `graph_seed`.
Граф это независимая переменная, он обязан быть одинаковым во всех прогонах.

**Метрики логируются и на лучшей эпохе по val, и на последней.** Защита от
претензии «вы кандидата X недообучили».
