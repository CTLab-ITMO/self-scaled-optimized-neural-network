# Что запускать, в каком порядке и сколько это займёт

Оценки времени — для **RTX 3060 12 ГБ**. Где написано «на процессоре», там
карта не нужна и не даст выигрыша: задача мелкая, GPU на ней недогружена.

Все команды можно прерывать в любой момент — Ctrl-C, сон ноутбука, отключение
питания. Повторный запуск той же команды продолжит с места обрыва. Ниже это
отдельно отмечено у каждого шага.

---

## Шаг 0. Окружение — 5 минут, один раз

```bash
./setup_env.sh
```

Определит железо, поставит нужную сборку torch в `.venv`, скачает MNIST.
Проверить, что всё живо:

```bash
.venv/bin/python src/model.py --dev
```

---

## Шаг 1. Правила на решётке — 40 минут

Ядро пункта 4 задания. Пять правил (два контроля и три настоящих), один тип
графа, один сид. Быстрая версия, чтобы увидеть картину.

```bash
./run_refine.sh --quick
```

```bash
.venv/bin/python src/refine.py --summary
```

**Что смотреть.** Обгоняет ли хоть одно правило `corr_greedy`. Оно обновляет
граф только по корреляциям, без обученной сети. Если умные правила его не
бьют — статистики модели ничего не добавляют, и это законченный отрицательный
результат, а не неудача.

Прерываемо: состояние пишется после каждого раунда.

---

## Шаг 2. Полный перебор на четырёх типах графов — 1.5–2 часа

Пять правил × четыре типа истинного графа × три сида = 60 прогонов.

```bash
./run_refine.sh
```

```bash
./run_refine.sh --status
```

**Зачем четыре типа.** Средняя степень у них от 3.6 до 7.4, разброс степеней
от 0.0 до 1.7. Вывод, полученный только на решётке, может оказаться её
свойством — как уже случилось с выводом «больше соседей вредно».

Замерено: 43.6 с на раунд при d = 144 на процессоре, то есть 4.4 часа на весь
перебор. На карте эти тензоры мелкие (144×144), выигрыш скромный — считай
1.5–2 часа. **Здесь карта помогает мало**, можно спокойно гонять на ноутбуке
фоном.

Прерываемо.

---

## Шаг 3. Правила на MNIST — 3–4 часа, **нужна карта**

Здесь d = 784 и 55 000 объектов, то есть примерно в 385 раз больше вычислений
на раунд, чем на синтетике. На процессоре это недели, на 3060 — вечер.

Флага для MNIST в `refine.py` пока нет, его надо дописать (полчаса работы):
подать `data.load_data()` вместо `synth_context`. Восстановление структуры там
не считается — истинного графа нет, — поэтому смотреть придётся только на
точность и на сравнение с `knn_corr_k8`.

Опорная точка для оценки: один прогон GCN при d = 784 и 150 эпохах занимал на
этой карте **598 секунд** (медиана по 110 прогонам). Раунд в 20 эпох — около
80 секунд, шесть раундов — 8–10 минут, пятнадцать прогонов (5 правил × 3
сида) — 2.5–3 часа.

---

## Шаг 4. Свести результаты — вечер работы руками

Дописать в `FINDINGS.md` и в краткий отчёт:

* таблицу «правило × тип графа» по точности и по восстановлению структуры;
* ответ на главный вопрос задания — можно ли улучшить модель, автоматически
  ища связи между признаками, не зная природы данных.

## Итого

| шаг | время | нужна карта |
|---|---|---|
| 0. Окружение | 5 мин | нет |
| 1. Правила на решётке | 40 мин | нет |
| 2. Четыре типа графов | 1.5–2 ч | почти нет |
| 3. MNIST | 3–4 ч | **да** |

**Около шести часов машинного времени на всё.** Из них карта нужна только на
третьем шаге.

---

## Чего в этом плане нет и почему

**CIFAR-10.** Отложен до того, как разберёмся с MNIST, либо на другого
человека. Там 3072 признака вместо 784, матрица смежности вчетверо больше.

**`run_series.sh`, 48 часов.** Это отдельная линия работы про глубину сети и
сравнение архитектур. **В задании её нет** — она выросла из первой серии по
MNIST. Для сдачи не нужна; имеет смысл, только если пойдёте в статью, потому
что там лежит проверка, закрывающая единственную дыру в главном результате
первой серии (сейчас он опирается на одну случайную перестановку вместо
выборки из десяти).

**Более устойчивая метка в синтетике.** Известное ограничение: «число связных
компонент» ломается от удаления одной вершины-моста, поэтому шкала сложности
получается крутой. Для основных выводов не мешает — они снимаются при нулевом
шуме.
