# План работы: влияние матрицы смежности A на качество GNN

Обозначения (без LaTeX):

```
d          число вершин = число признаков (MNIST 28x28 -> d = 784)
n          число объектов выборки
A          матрица смежности, [d, d], симметричная, бинарная, diag(A) = 0
Â          нормализованная матрица распространения (см. ниже)
π          фиксированная перестановка признаков
σ          случайная перестановка (для контролей), σ ≠ π
m(A)       метрика качества модели, обученной при данной A
|E|, ρ     число рёбер и плотность графа
ℰ(A)       энергия Дирихле сигнала на графе (см. §0.4)
```

Модель, зафиксированная во всех прогонах:

```
Â = D^(-1/2) (A + I) D^(-1/2),     D_vv = Σ_u (A + I)_vu
H^(l+1)   = ReLU( Â H^(l) W^(l) )
h_i       = mean_v H^(L)[i, v, :]           # readout
ŷ_i       = softmax( W_out h_i )
```

---

## 0. Наблюдения, определяющие дизайн эксперимента

### 0.1. Граф — единственный источник идентичности вершины

Признак вершины скалярный (F_in = 1), вершины для модели не пронумерованы,
GNN перестановочно-эквивариантна, readout — среднее.

Следствие: **модель физически не может отличить вершину v от вершины u ничем,
кроме структуры их окрестностей в A.**

Обе границы шкалы считаются аналитически, до всякого обучения:

**Пол — пустой граф.** При `A = 0` имеем `A + I = I`, `D = I`, значит `Â = I`:

```
ŷ = softmax( W_out · mean_v MLP(x_v) )
```

Это функция от **мультимножества значений пикселей**, то есть от гистограммы
интенсивностей. Ожидание: 30–45 %.

> Заметим: `A = 0` и `A = I` дают буквально одну и ту же модель (в обоих случаях
> `A + I = I`). Это **один** бейзлайн, а не два.

**Патология — полный граф.** При `A = K_d` имеем `A + I = J` (все единицы),
`D = d·I`, значит `Â = J/d`. Тогда `Â H` — это broadcast среднего по вершинам,
и уже после первого слоя **все вершины имеют одинаковое представление**.
Модель схлопывается в функцию одного скаляра — среднего значения пикселя
(«количество чернил»). Ожидание: 20–30 %.

Отсюда санити-чек пайплайна (фаза Ф2):

```
mlp  ≫  grid4  ≫  empty  >  complete ≈ 20-30 %
```

Если порядок другой — искать баг, дальше не идти.

### 0.2. Перестановка π ничего не меняет математически

Если применить π и к данным, и к графу, получится в точности исходная задача:
`P_π X` на графе `P_π A P_π^T` изоморфно `X` на `A`.

То есть π — не источник сложности, а **запрет на читерство**: нельзя строить
граф из координат пикселей, потому что после перемешивания координаты
неизвестны.

Практический вывод:

* решётка 28×28, перенесённая через известную нам π, — это **оракул**
  (верхняя граница по структуре), а не метод; так и подписывается;
* **честные** методы строят A только из обучающей выборки — корреляции между
  пикселями, kNN по ним — не заглядывая в π.

### 0.3. Главный контроль: изоморфный, но несогласованный граф

Все чисто структурные характеристики A — плотность, спектр, кластеризация,
диаметр, распределение степеней — **инвариантны относительно перенумерации
вершин**. А m(A) — нет.

Отсюда идеальный контроль: взять решётку и переклеить её к вершинам по
случайной перестановке σ ≠ π:

```
A_misaligned = P_σ · A_grid · P_σ^T
```

Этот граф **изоморфен** решётке: у него побитово те же |E|, ρ, спектр, диаметр,
коэффициент кластеризации. Отличается только привязка вершин к пикселям.

Если оракул сильно бьёт этот контроль, то выигрыш даёт **согласованность графа с
данными**, а не «решётчатость» как таковая.

Отсюда основной тезис работы (гипотеза H1, §5):

> **m(A) не является функцией класса изоморфизма A.**
> Поэтому предсказывать качество по структурным дескрипторам принципиально
> невозможно — нужны дескрипторы, зависящие от данных.

### 0.4. Что предсказывает m(A) на самом деле

GCN — низкочастотный фильтр: `Â ≈ I − L_norm`, повторное применение подавляет
высокие частоты лапласиана. Значит граф хорош тогда, когда **сигнал на нём
гладкий**: соседи по A имеют похожие значения пикселей.

Мера — энергия Дирихле, нормированная по числу рёбер и по дисперсии внутри
объекта (чтобы была сравнима между графами разной плотности):

```
                    (1/|E|) · Σ         (x_iu − x_iv)²
                              (u,v)∈E
ℰ(A) = mean_i  ─────────────────────────────────────────
                          Var_v( x_iv )
```

Плюс ассортативность сигнала по рёбрам:

```
r(A) = corr( x_iu , x_iv )   по всем рёбрам (u,v)∈E и всем объектам i
```

Оба дескриптора зависят **и от A, и от данных**, и считаются за секунды без
всякого обучения.

**Гипотеза H2:** m(A) сильно антикоррелирует с ℰ(A). Если подтвердится —
получаем дешёвый предиктор качества графа без обучения. Это самый интересный
потенциальный результат работы.

## 1. Бюджет вычислений

Железо: **RTX 3060 12 GB**, 8 CPU-ядер, 31 GB RAM.

### 1.1. Почему плотная реализация, а не torch_geometric

Топология одна на всю выборку, различаются только признаки вершин. Значит слой —
это обычный батчевый матмул с предпосчитанной Â:

```
H: [B, d, F]   ->   reshape   ->   [d, B·F]
Â @ H_reshaped                      # один большой GEMM, отличная утилизация GPU
```

Â считается **один раз на кандидата** и лежит на GPU. `torch_geometric` не нужен:
dense-GCN численно тождествен `GCNConv`, но не пересобирает `edge_index` на
каждый батч и не гоняет scatter-ядра. На d = 784 это кратно быстрее.

Побочный плюс: все кандидаты — плотные матрицы одного размера, поэтому
**время прогона одинаково для решётки и для полного графа**. Нет конфаунда
«плотный граф считается дольше».

### 1.2. Оценка стоимости

Доминирующая операция — распространение `Â H`: d²·F MAC на объект на слой.
При L = 3, hidden = 64, d = 784:

```
слой 1 (F_in = 1):  Â@X сначала, потом @W  ->  784² · 1  +  784 · 64  ≈  0.7 M MAC
слой 2:                                        784² · 64             ≈ 42.5 M MAC
слой 3:                                                              ≈ 42.5 M MAC
--------------------------------------------------------------------------------
forward  ≈ 86 M MAC ≈ 0.17 GFLOP на объект
fwd+bwd  ≈ 0.5 GFLOP на объект
```

| | значение |
|---|---|
| на эпоху (55k train) | ≈ 28 TFLOP |
| RTX 3060, реально достижимо на GEMM | ≈ 8–12 TFLOPS (FP32), больше на TF32 |
| **время эпохи** | **≈ 3–5 с** |
| **прогон, 30 эпох** | **≈ 2–4 мин** |
| **весь эксперимент, 110 прогонов** | **≈ 4–6 ч** |

VRAM: весь MNIST на GPU — 220 MB; Â — 2.5 MB; активации при B = 256 — под 300 MB.
**Итого меньше 1 GB из 12.** Датасет держим на GPU целиком, `DataLoader` не нужен
вообще, индексируем тензор перестановкой индексов.

### 1.3. Решения по масштабу

* **Полное разрешение 28×28, d = 784.** Даунсэмплинг не нужен — и это не только
  вопрос скорости: на 784 вершинах структура графа богаче и содержательнее.
  После пулинга 2×2 соседние пиксели коррелируют почти идеально, задача
  становится проще и менее интересной.
* **Полная выборка:** 55k train / 5k val / 10k test (стандартный тест MNIST).
* **S = 5 сидов.** Если пилот (Ф3) покажет ≤ 2 мин на прогон — поднимаем до 10,
  доверительные интервалы станут заметно надёжнее почти бесплатно.
* **Runpod не нужен.** 3060 закрывает задачу с запасом.
* **Режим разработки:** для фаз Ф1–Ф4 держим флаг `--dev`, который включает
  пулинг 2×2 (d = 196) и 5k train. Цикл отладки — секунды, а не минуты.
  На финальные прогоны флаг выключается.

Параллельные прогоны на одной карте смысла почти не имеют: задача
compute-bound, процессы будут делить SM. Проще гнать последовательно.

## 2. Фиксируемая часть (константы во всех прогонах)

Всё в `configs/fixed.yaml`, хеш конфига логируется рядом с результатами.

**Данные**

* MNIST, стандартное разбиение; 55k train / 5k val (стратифицированно) / 10k test.
* Нормализация — **только глобальная**: `x ← x / 255`.
  ⚠️ **Нельзя** делать по-пиксельную стандартизацию: у краевых пикселей
  `std ≈ 0`, деление на неё раздувает шум в огромные значения и ломает
  эксперимент.
* Перестановка π: `np.random.default_rng(1234).permutation(d)`, сохраняется в
  `artifacts/pi.npy`, **одна на все прогоны**.

**Архитектура**

* GCN, L = 3 слоя, hidden = 64, ReLU, без dropout, без BatchNorm.
* Â по формуле выше, считается один раз на кандидата, кешируется.
* readout — mean по вершинам; голова — один Linear 64 → 10.
* **Никаких positional encodings и номеров вершин.** Они дали бы модели
  идентичность вершины в обход A и обнулили бы весь эксперимент (§0.1).

**Обучение**

* Adam, lr = 1e-3, weight decay = 0, batch = 256, 30 эпох, без scheduler.
* Cross-entropy.
* Отбор модели — лучшая эпоха по val-accuracy, критерий одинаков для всех A.
* Логируем **обе** метрики: на последней эпохе и на лучшей по val. Защита от
  претензии «вы кандидата X недообучили».

**Сиды**

* S = 5, seeds {0,1,2,3,4}. Сид управляет инициализацией весов и порядком
  батчей. Разбиение данных и π от сида **не зависят**.

## 3. Варьируемая часть: набор кандидатов

Все A — симметричные, бинарные, с нулевой диагональю. Каждый билдер
регистрируется в `graphs.py` и возвращает `(A, meta)`.

### Группа R — референсы (границы шкалы)

| id | Граф | Зачем |
|---|---|---|
| `mlp` | не GNN: MLP на сырых d признаках | **Потолок**, ~98 %. Сколько информации в данных вообще есть |
| `empty` | A = 0 | **Пол**: функция гистограммы интенсивностей (§0.1) |
| `complete` | K_d | Патология: коллапс в среднее значение пикселя (§0.1) |

### Группа O — оракулы (используют знание π, помечаются как «нечестные»)

| id | Граф |
|---|---|
| `grid4` | 4-связная решётка 28×28, перенесённая через π |
| `grid8` | 8-связная (с диагоналями) |
| `grid_r2` | все пиксели на расстоянии ≤ 2 |

### Группа D — data-driven (честные, строятся **только по train**)

| id | Граф |
|---|---|
| `knn_corr_k4` / `k8` / `k16` | kNN по \|corr(x_u, x_v)\| между столбцами-пикселями, симметризация через OR |
| `thr_corr` | порог на \|corr\|, подобранный так, чтобы плотность совпала с `grid4` |

> Кандидаты по взаимной информации и по матрице точности были реализованы и
> убраны: они стоили четверти сложности `graphs.py` (оценка MI через one-hot и
> матмул, обращение вырожденной ковариации с гребнем), а для MNIST ранжируют
> пары пикселей почти так же, как обычная корреляция - зависимость там
> монотонная. Именно кандидат по MI породил баг с разрешением ничьих в
> `argsort`: сложность окупилась багом, а не результатом.

⚠️ **Мёртвые пиксели.** В MNIST ~65–70 краевых пикселей константны на train,
`std = 0` → корреляция NaN. Обработка фиксируется явно: `corr := 0` для таких
пар. Такие вершины остаются изолированными — их число пишется в `meta` и
учитывается при интерпретации.

### Группа C — контроли (каждый согласован по плотности со своим оригиналом)

| id | Граф | Что изолирует |
|---|---|---|
| `grid4_misaligned` | `P_σ A_grid P_σ^T`, случайная σ | **Главный контроль.** Изоморфен `grid4` → изолирует *согласованность с данными* от *структуры* |
| `er_grid4` | Эрдёш–Реньи, ρ = плотности `grid4` | «Это просто рёбра?» |
| `er_knn8` | Эрдёш–Реньи, ρ = плотности `knn_corr_k8` | То же для data-driven |
| `regular4` | случайный 4-регулярный | Распределение степеней |
| `config_knn8` | конфигурационная модель на степенной последовательности `knn_corr_k8` | Степени отдельно от топологии |

> **Правило: ни одно утверждение вида «граф X помогает» не принимается без
> своего density-matched контроля.** Без этого «kNN лучше пустого графа» не
> значит ничего.

### Группа W — кривая деградации

`ws_p` — перепроводка Уоттса–Строгатца графа `grid4` с долей
`p ∈ {0, 0.05, 0.1, 0.25, 0.5, 1.0}`.

При p = 0 это `grid4`, при p = 1 почти `regular4`. Плотность и распределение
степеней сохраняются **точно**, меняется только локальность. Самый
информативный график всей работы: не точка, а кривая.

### Группа P — патологии (дёшево, задают шкалу)

`star`, `path`, `blocks` (кластеры по k-means на корреляциях, внутри — клики,
между — пусто).

**Итого:** 22 графа × 5 сидов = **110 прогонов**, включая 5 прогонов MLP.

## 4. Что записываем на каждый прогон

Одна строка в `results.csv` на пару (граф, сид).

**Метрики качества, test:** accuracy, macro-F1, macro-precision, macro-recall,
balanced accuracy, cross-entropy loss. Матрица ошибок → отдельный `.npy`.
Те же метрики на val и train (диагностика переобучения) + номер лучшей эпохи.

**Структурные дескрипторы A** (не зависят от данных, считаются один раз на граф):
|E|, средняя степень, ρ, std степеней, число компонент связности, размер
гигантской компоненты, число изолированных вершин, средний коэффициент
кластеризации, средняя длина кратчайшего пути и диаметр (на гигантской
компоненте), спектральная щель λ₂(L_norm), λ_max(L_norm).

**Дескрипторы «граф + данные»** (главное, §0.4): ℰ(A), r(A), доля рёбер между
пикселями одного типа (фон / чернила).

**Диагностика oversmoothing:** средняя попарная косинусная близость эмбеддингов
вершин на выходе слоя L, усреднённая по тесту. Отвечает на вопрос
«плохой граф или переглаженные представления».

**Служебное:** время обучения, хеш конфига, версия кода, сид.

## 5. Гипотезы

Не «таблица ради таблицы» — три фальсифицируемых утверждения.

**H1. m(A) не является функцией класса изоморфизма A.**
Тест: `grid4` против `grid4_misaligned`. Графы изоморфны, все структурные
дескрипторы совпадают побитово. Если accuracy различается значимо — H1
подтверждена, и вывод: **структурных характеристик графа принципиально
недостаточно** для предсказания качества.

**H2. m(A) предсказывается энергией Дирихле сигнала ℰ(A).**
Тест: ранговая корреляция Спирмена между средней метрикой и ℰ(A) по всем
кандидатам. Ожидание — сильная отрицательная. Практический смысл: предиктор
качества графа **без обучения**.

**H3. Зависимость от плотности — перевёрнутая U.**
Слишком разреженный граф → агрегировать нечего (стремится к `empty`);
слишком плотный → oversmoothing при фиксированном L (стремится к `complete`).
Тест: график метрики против ρ по всем кандидатам, плюс диагностика
oversmoothing из §4 как объяснение правой ветви.

```
gnn/

  src/
    data.py              # MNIST, π, split, тензоры на GPU; кеш в .npz
    graphs.py            # реестр билдеров A: name -> (A, meta); нормализация -> Â
    graph_stats.py       # структурные + сигнальные дескрипторы
    model.py             # DenseGCN (Â @ H @ W, батчево) + MLP-референс
    metrics.py           # accuracy, macro-F1, confusion, loss
    train.py             # один прогон: (graph_name, seed) -> dict метрик
    run_all.py           # цикл по кандидатам × сидам, дозапись в results.csv
    analyze.py           # таблицы, графики, тесты гипотез
  artifacts/             # pi.npy, кеш данных, кеш Â, матрицы ошибок
  results/               # results.csv (append-only), figures/
  (итоги -> FINDINGS.md и results/отчёт_*.html)
```

Принципы:

* `run_all.py` **дописывает** строки в `results.csv` и пропускает уже
  посчитанные пары (граф, сид) → прогон прерываемый и возобновляемый;
* каждая A и её Â кешируются на диск;
* детерминизм: `torch.use_deterministic_algorithms(True)`. Здесь это реально

## 9. Опциональная фаза Ф8 (на повышенную оценку): оптимизация A

Задание разрешает менять только граф. Логичное развитие — не перебирать
кандидатов, а **искать** A.

* **Дискретный жадный поиск.** Старт с пустого графа, добавляем рёбра с
  наибольшим \|corr\| батчами по 100, каждые T шагов переобучаем и смотрим на
  val. Даёт кривую «качество против бюджета рёбер».
* **Непрерывная релаксация.** Обучаем логиты S размера [d, d],
  `A_soft = sigmoid((S + S^T)/2)`, с L1-регуляризацией на разреженность. Затем
  бинаризуем по порогу и **переобучаем с нуля по общему фиксированному
  протоколу** — иначе сравнение нечестное.

Сильный результат: найденный поиском граф обгоняет оракульную решётку. Это
означало бы, что решётка не оптимальна для GCN даже при известной геометрии.

## 10. Риски и типовые ошибки

1. **Утечка.** Корреляции между пикселями считаются **только на train**. Самая
   частая ошибка в таких работах — считать их на всей выборке.
2. **Конфаунд плотности.** Любое сравнение — только против density-matched
   контроля (§3, группа C).
3. **По-пиксельная нормализация.** Ломает эксперимент (§2). Только глобальная.
4. **Positional encodings.** Дают идентичность вершин в обход A → эксперимент
   теряет смысл (§0.1).
5. **Oversmoothing против «плохого графа».** Плотные графы падают из-за
   переглаживания при фиксированном L, а не потому что «структура
   неинформативна». Это надо измерять (§4) и писать в отчёте прямо.
6. **Мёртвые пиксели.** `std = 0` → NaN в корреляциях. Обработка фиксируется
   явно, число изолированных вершин логируется.
7. **Неравный бюджет обучения.** Разные A сходятся с разной скоростью. Защита:
   одинаковое число эпох + логирование метрики и на последней эпохе, и на
   лучшей по val.
8. **Соблазн выбросить неудобного кандидата.** Все запущенные кандидаты попадают
   в таблицу, включая патологии — они и задают шкалу.
